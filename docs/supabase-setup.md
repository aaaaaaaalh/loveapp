# 两个人开始使用

Supabase 已接入用户同意复用的 LoveApp Free 组织项目（新加坡）。本地配置已自动写入被 Git 忽略的 .env.local，不需要复制 SQL、建表或填写密钥。

1. 打开 http://127.0.0.1:5173/，用自己的邮箱和至少 8 位密码注册，直接进入，不需要确认邮件。
2. 由石若瀚创建空间，默认名字为石若瀚 / 张潋镕，相恋日期为 2026-04-20。照片、留言、愿望和礼物都是空白。
3. 在「我的」生成邀请码。张潋镕用自己的账号注册，选择「加入对方的空间」，输入邀请码。不要两个人分别创建空间。
4. 此后各自登录即可查看和记录同一空间的内容。邀请码一次有效，空间最多两名成员。

本地预览只能在这台电脑访问。可用普通窗口和无痕窗口分别登录体验双人使用；目前没有部署公网网站，因此还不能让异地手机直接打开此 localhost 地址。

## 本地启动

在 E:\loveapp 运行 npm.cmd install，然后运行 npm.cmd run dev。

账号、数据库记录和私有照片保存在 Supabase，刷新会重新读取；开发服务器关闭不会删除云端内容。移除环境变量才会进入独立的内存演示模式，演示记录刷新即清空，且不会自动迁移到云端。

## 已完成的技术配置

- 官方 CLI 2.120.0，工作区内安装；命令入口 npm.cmd run supabase -- <命令>。
- 项目引用 rnramhagybuibobmketv；使用现有 Free 项目，没有新购资源、升级套餐或部署。
- 已应用 202610100001_private_space.sql，保存标准迁移历史；六张业务表启用 RLS，照片桶私有，订阅已配置。
- 前端只使用 VITE_SUPABASE_URL 与 VITE_SUPABASE_PUBLISHABLE_KEY，不使用管理密钥。
- 已设置回调 http://127.0.0.1:5173/ 和 http://localhost:5173/。邮箱注册无需确认；匿名登录关闭，密码最少 8 位。
- 官方登录凭据目录 .supabase-cli/、关联缓存 supabase/.temp/、.env.local 均被 Git 忽略。不要分享这些文件。

常规 db push --dry-run 因本机 PostgreSQL 直连失败未完成；实际通过官方 CLI db query --linked 先执行完整迁移并回滚，确认未留下变更，再执行同一迁移的提交事务及迁移历史登记。没有执行 reset 或清空已有用户数据。详细验收见 [云端验收报告](cloud-cli-validation.md)。

当前没有找回密码、邮件服务配置、头像上传或公网部署；按两人私用的简单范围保留现有界面和功能。
